# 个人博客系统 开发计划文档

> 版本：v1.1　·　日期：2026-11-18　·　开发模型：瀑布模型（Waterfall）

## 0. 项目概述

### 0.1 项目目标
开发一个**前后端分离的个人博客系统**，作为入门级全栈项目，完整走通「需求分析 → 设计 → 编码 → 测试 → 部署上线」全流程，最终部署到云服务器上可公开访问，并沉淀为可写入简历 / 作品集的项目。

### 0.2 技术栈
| 层 | 技术 | 版本 | 说明 |
|----|------|------|------|
| 后端框架 | Spring Boot | 3.2.x | 需要 JDK 17 |
| ORM | MyBatis-Plus | 3.5.x | 单表 CRUD、分页、逻辑删除、自动填充 |
| 数据库 | MySQL | 8.0 | 持久化存储 |
| 缓存 | Redis | 7.x | 二级缓存、限流、浏览量计数 |
| 本地缓存 | Caffeine | 3.x | 一级缓存（进程内） |
| 认证 | Spring Security + JWT | jjwt 0.12.x | 登录鉴权 |
| 接口文档 | Knife4j | 4.x | 基于 OpenAPI3，在线调试 |
| 前端 | Vue 3 + Vite | Vue 3.4 / Vite 5 | 前台 + 后台 SPA（与 WeBlog 一致） |
| 部署 | Docker Compose + Nginx | — | 容器化上线 |
| 版本控制 | Git + GitHub | — | 全程提交 |

> 说明：前端采用 **Vue 3 + Vite**（与 WeBlog 一致），单个项目内用路由区分前台展示与后台管理；配套 Vue Router、Pinia、Axios、Element Plus。

### 0.3 参考项目
本项目参考开源项目 [WeBlog](https://github.com/weiwosuoai/WeBlog)（Spring Boot + MyBatis-Plus + MySQL + Vue3，约 700 星），在其基础上做三处调整：

1. 前端沿用 **Vue 3 + Vite**（与 WeBlog 一致），补充 Pinia 状态管理；
2. **补充 Redis 能力**：Caffeine + Redis 多级缓存、Lua 限流、浏览量计数；
3. 后端由 Maven 多模块简化为**单模块 + 清晰包分层**，降低入门复杂度（逻辑等价）。

### 0.4 开发模型：瀑布模型
瀑布模型按顺序推进，每个阶段有明确的交付物与评审关口（Gate），前一阶段评审通过后才进入下一阶段：

| 阶段 | 名称 | 主要交付物 | 评审关口 |
|------|------|-----------|---------|
| 一 | 需求分析 | 功能清单、优先级、非功能需求 | 需求评审 |
| 二 | 系统设计 | 架构图、数据库 DDL、接口清单、缓存/限流设计、前端页面清单 | 设计评审 |
| 三 | 编码实现 | 可运行的后端 + 前端代码（含中文注释） | 代码评审 |
| 四 | 测试 | 测试用例与测试报告 | 测试验收 |
| 五 | 部署上线 | 线上可访问站点 + 部署文档 | 上线验收 |

- **博主（管理员）**：发布和管理文章、分类、标签、评论，配置站点信息。
- **访客（读者）**：浏览文章，按分类 / 标签 / 归档检索，发表评论。

## 2. 阶段二：系统设计

### 2.1 总体架构（前后端分离）

    浏览器（访客 / 管理员）
                │ HTTPS
                ▼
    ┌───────────────────────────────┐
    │  Nginx（静态资源 + 反向代理）      │
    │   /          → Vue 前端(前台+后台) │
    │   /api/**    → 后端 REST API     │
    └───────────────┬───────────────┘
                    │
                    ▼
    ┌───────────────────────────────┐
    │   Spring Boot 后端（REST API）   │
    │  Controller → Service → Mapper │
    │  JWT 鉴权 / 统一返回 / 全局异常   │
    └──────┬──────────────┬─────────┘
           │              │
    ┌──────▼────┐   ┌─────▼──────────┐
    │  MySQL 8   │   │   Redis 7       │
    │ 持久化存储  │   │ 缓存/限流/计数    │
    └───────────┘   │ + Caffeine(本地) │
                    └─────────────────┘

|----|------|------|

| Spring Boot | 3.2.x | 主流、教程多，避免 4.x 过新 |

### 2.3 数据库设计
共 7 张表，统一带逻辑删除字段 deleted 与审计字段 create_time / update_time。

#### 2.3.1 ER 关系

    user 1 ──── N article          （作者 → 文章）
    category 1 ──── N article      （分类 → 文章）
    article N ──── N tag           （多对多，经 article_tag）
    article 1 ──── N comment       （文章 → 评论）
    user 1 ──── N comment          （用户 → 评论）

#### 2.3.2 表结构清单
| 表名 | 说明 | 关键字段 |
|------|------|---------|
| user | 用户 | id, username, password(bcrypt), nickname, avatar, email |
| category | 分类 | id, name, description, sort |
| tag | 标签 | id, name |
| article | 文章 | id, title, summary, content(markdown), cover, author_id, category_id, status(草稿/发布), view_count, is_top |
| article_tag | 文章-标签 | id, article_id, tag_id |
| comment | 评论 | id, article_id, user_id, parent_id(二级回复), content, status |
| site_config | 站点设置 | id, config_key, config_value |

> 完整 DDL 将在阶段三 M1 落成于 sql/schema.sql + sql/data.sql（含初始化数据与默认管理员账号）。

### 2.4 接口设计
- **风格**：RESTful，统一前缀 /api；后台管理接口前缀 /api/admin/**（需 JWT）。
- **统一返回结构**：code=0 表示成功，非 0 表示失败，data 承载数据：

    { "code": 0, "message": "OK", "data": { ... } }

- **分页参数**：page（页码）、size（每页条数），返回 { records, total, current, size }。

#### 接口清单（核心）
| 分组 | 方法 | 路径 | 说明 | 鉴权 |
|------|------|------|------|------|
| 文章 | GET | /api/article/page | 分页文章列表（缓存） | 否 |
| 文章 | GET | /api/article/{id} | 文章详情（缓存 + 浏览量） | 否 |
| 文章 | POST | /api/admin/article | 新建文章 | 是 |
| 文章 | PUT | /api/admin/article/{id} | 编辑文章 | 是 |
| 文章 | DELETE | /api/admin/article/{id} | 删除文章 | 是 |
| 分类 | GET | /api/category/list | 分类列表（缓存） | 否 |
| 标签 | GET | /api/tag/list | 标签列表（缓存） | 否 |
| 评论 | GET | /api/comment/page | 文章评论列表 | 否 |
| 评论 | POST | /api/comment | 发表评论（限流） | 否 |
| 认证 | POST | /api/auth/login | 登录（限流） | 否 |
| 认证 | GET | /api/auth/me | 当前用户信息 | 是 |
| 站点 | GET | /api/site/config | 站点配置（缓存） | 否 |
| 站点 | PUT | /api/admin/site/config | 更新站点配置 | 是 |

> 完整接口文档（含请求 / 响应示例）由 Knife4j 在编码阶段自动生成，开发时可在 http://localhost:8080/doc.html 在线调试。

### 2.5 Redis 缓存与限流设计（本项目的重点补充）

#### 2.5.1 Caffeine + Redis 多级缓存
读路径（Cache-Aside 旁路缓存模式）：

    请求 → Caffeine(一级) → 命中返回
              │ 未命中
              ▼
           Redis(二级) → 命中：回填 Caffeine 后返回
              │ 未命中
              ▼
           MySQL → 回填 Redis + Caffeine → 返回

缓存键与过期时间：
| 键 | 内容 | TTL |
|----|------|-----|
| blog:article:{id} | 文章详情 | 30 分钟 |
| blog:article:page:{page}:{categoryId}:{tagId}:{keyword} | 文章分页列表 | 5 分钟 |
| blog:category:list | 分类列表 | 30 分钟 |
| blog:tag:list | 标签列表 | 30 分钟 |
| blog:site:config | 站点配置 | 1 小时 |

缓存一致性（写路径）：文章 / 分类 / 标签 / 站点配置变更时，**精准删除**对应的 Redis key 并清空 Caffeine 本地缓存，不采用全局清空，避免误伤。

#### 2.5.2 Redis Lua 限流
- 用 Redis EVAL 执行 Lua 脚本实现**滑动窗口限流**，原子操作，防止并发绕过。
- 典型应用：登录接口（每 IP 每分钟最多 5 次，防暴力破解）、发评论接口（每 IP 每分钟 10 次，防刷）。
- 键设计：blog:ratelimit:{ip}:{api}，超限返回统一错误码（4290）。

#### 2.5.3 浏览量统计
- 文章访问时执行 INCR blog:view:{articleId}，定时任务批量回写 MySQL 的 view_count，避免每次访问都写库。
- 列表 / 详情的浏览数展示优先读 Redis，读不到回退 MySQL。

### 2.6 认证鉴权设计（JWT）
- 登录成功签发 JWT（含 userId、username），有效期 24 小时；前端存 localStorage，请求头携带 Authorization: Bearer <token>。
- 后端用 Spring Security 过滤器链：公开接口放行，/api/admin/** 校验 JWT。
- 密码用 BCrypt 加密存储。

### 2.7 前端设计（Vue 3 + Vite，单项目双路由）
采用**单个 Vue3 + Vite 项目**，用 Vue Router 区分前台（公开）与后台（需登录）两组路由，降低入门复杂度（WeBlog 拆成两个项目，后期可再拆分）。

| Vite | 5.x | 开发服务器 + 构建 |
| Vue Router | 4.x | 前台 / 后台路由 |
| Pinia | 2.x | 状态管理（用户 token、站点配置） |
| Axios | 1.x | HTTP 请求，拦截器统一注入 token、统一处理错误 |
| Element Plus | 2.x | 后台管理 UI 组件库 |
| markdown-it + highlight.js | — | 前台 Markdown 渲染 + 代码高亮 |

## 3. 阶段三：编码实现
按里程碑推进，每个里程碑结束都是「可运行、可验证」的版本（借鉴 White-Jotter「缓步小跑」节奏）。

| 里程碑 | 内容 | 验收标准 |
|--------|------|---------|
| M1 | 后端骨架 + 建库建表 + 统一返回/异常 + JWT 登录 | 服务能启动，/api/auth/login 可登录，Knife4j 可见接口 |
| M2 | 文章 / 分类 / 标签 / 评论 CRUD | 后台接口完整可用，可发文章 |
| M3 | 前台页面（Vue） | 首页 / 详情 / 分类 / 标签 / 归档可浏览 |
| M4 | 后台管理页面（Vue） | 可登录后台，管理文章 / 分类 / 标签 / 评论 / 站点 |
| M5 | Redis：多级缓存 + Lua 限流 + 浏览量 | 命中缓存、限流生效、浏览量正确累计 |
| M6 | 前后端联调 + 打磨 | 全功能可用，无明显 bug |

### 3.1 编码规范（针对本项目的注释要求）
- **包分层注释**：每个包名语义清晰，Service / Controller 写职责说明。
- **类级注释**：每个类用 JavaDoc 说明「是什么、负责什么」。
- **方法级注释**：关键方法写「入参 / 出参 / 做了什么」，复杂逻辑逐行 / 逐段注释。
- **关键逻辑注释**：多级缓存读写路径、Lua 限流、JWT 过滤链、统一异常处理必须加中文注释说明「为什么这么做」。
- **命名规范**：Controller 用 REST 语义（list / get / create / update / delete），Service 接口 + Impl 实现，DTO 用 Request / Response 后缀区分。
- 前端 Vue 组件（script setup 语法）写中文注释，关键方法加 JSDoc；页面按 front/ 与 admin/ 分目录，公共逻辑抽到 api/、utils/。

## 5. 阶段五：部署上线
### 5.1 环境准备
- 云服务器（阿里云 / 腾讯云轻量应用服务器即可，2 核 2G 起步），安装 Docker + Docker Compose。
- 域名（可选）+ DNS 解析 + HTTPS 证书（Let's Encrypt / 云厂商免费证书）。

### 5.2 Docker Compose 一键部署
- 服务：mysql、redis、blog-backend、nginx（前端打包产物 dist/ 挂载进 nginx）。
- 后端打成 jar 包，用多阶段 Dockerfile 构建镜像；前端用 Vite 构建成静态文件。

### 5.3 Nginx 与 HTTPS
- 前端静态资源（Vite 打包后的 dist/）由 Nginx 直接托管；/api/** 反向代理到后端。
- 配置 Vue Router history 模式回退（所有路径指向 index.html）。
- 配置 HTTPS 与 HTTP→HTTPS 跳转。

## 8. 风险与应对
| 风险 | 影响 | 应对 |
|------|------|------|
| 前后台路由混在一个项目里 | 后期维护可能变复杂 | 按 front/ / admin/ 分目录，公共逻辑抽到 api/、utils/，跑通后再按需拆分成两个项目 |
| 多级缓存一致性难排查 | 出现缓存未更新 | 严格遵循「写时精准失效」，后台提供手动刷新缓存入口 |
| 环境 / 版本不匹配 | 启动失败 | 固定版本号，提供 README 与 Docker 一键环境 |
| 范围蔓延（想做太多功能） | 周期失控 | 严格按 P0 → P1 → P2 优先级，先交付 MVP 再迭代 |

## 附录
### A. 术语表
| 术语 | 含义 |
|------|------|
| 前后端分离 | 前端页面与后端 API 独立开发、独立部署，通过 HTTP 接口通信 |
| SPA | 单页应用，前端路由切换页面，不刷新整页 |
| REST API | 基于 HTTP 的接口设计风格 |
| JWT | 无状态令牌，用于登录鉴权 |
| 多级缓存 | 本地缓存(Caffeine) + 分布式缓存(Redis) 组合，减少回源 |
| Cache-Aside | 旁路缓存模式：读先查缓存，写时更新数据库并失效缓存 |
| Lua 限流 | 用 Redis 执行 Lua 脚本原子化地做访问频率限制 |
