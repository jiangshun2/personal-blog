# 阿里云 ECS 部署上线文档

> 适用项目：个人博客系统（Spring Boot 3 + Vue3 + MySQL 8 + Redis 7）
> 目标：把本地项目部署到阿里云 ECS，通过公网 IP / 域名访问
> 预计耗时：首次约 1~2 小时
> 部署方式：Docker Compose（Nginx + 后端 + MySQL + Redis）

## 一、部署架构

    用户浏览器
       │ HTTP(80) / HTTPS(443)
       ▼
    阿里云 ECS（公网 IP）
    ┌──────────────────────────────────────────────┐
    │  Docker Compose                              │
    │                                              │
    │  ┌──────────┐        ┌─────────────────────┐ │
    │  │  nginx   │───────▶│ backend(Spring Boot)│ │
    │  │ 80 / 443 │  /api  │       :8080         │ │
    │  │ 托管 dist │        └──────────┬──────────┘ │
    │  └──────────┘                   │            │
    │                        ┌────────▼─────────┐  │
    │                        │  mysql:8  :3306  │  │
    │                        └──────────────────┘  │
    │                        ┌──────────────────┐  │
    │                        │  redis:7  :6379  │  │
    │                        └──────────────────┘  │
    └──────────────────────────────────────────────┘

要点：
- 只有 Nginx 的 80 / 443 暴露到公网；
- MySQL、Redis、后端都只在 Docker 内部网络，不对公网开放端口；
- 前端 dist/ 由 Nginx 托管，/api/** 反向代理到后端。

## 二、前置准备

### 2.1 购买 ECS

| 项 | 建议 |
|----|------|
| 规格 | 2 核 2G 起步（预算足选 2C4G，构建更快） |
| 镜像 | Alibaba Cloud Linux 3.x 64 位（或 Ubuntu 22.04） |
| 系统盘 | 40G 起 |
| 带宽 | 1~3 Mbps 够个人博客用 |
| 地域 | 离你近的（如华东1-杭州） |

### 2.2 安全组（必须）

ECS 控制台 → 实例 → 安全组 → 配置规则 → 入方向，添加：

| 端口 | 协议 | 用途 | 授权对象 |
|------|------|------|---------|
| 22 | TCP | SSH 登录 | 你的公网 IP（或 0.0.0.0/0） |
| 80 | TCP | HTTP | 0.0.0.0/0 |
| 443 | TCP | HTTPS | 0.0.0.0/0 |

注意：3306（MySQL）和 6379（Redis）不要对公网开放。

### 2.3 域名（可选但推荐）

- 在阿里云买域名并完成实名认证；
- 域名解析：添加 A 记录，指向 ECS 公网 IP；
- 备案：国内服务器绑定域名需要 ICP 备案（阿里云控制台可办）。

## 三、连接服务器

本地终端执行（把 IP 换成你的公网 IP）：

    ssh root@你的公网IP

第一次连接输入 yes，再输入服务器密码。

## 四、安装 Docker 与 Docker Compose

### 4.1 Alibaba Cloud Linux 3 / CentOS 系

    # 安装依赖
    sudo yum install -y yum-utils

    # 添加阿里云 Docker CE 镜像源
    sudo yum-config-manager --add-repo https://mirrors.aliyun.com/docker-ce/linux/centos/docker-ce.repo

    # 安装 Docker 与 compose 插件
    sudo yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

    # 启动并设置开机自启
    sudo systemctl enable --now docker

    # 验证
    docker --version
    docker compose version

### 4.2 Ubuntu 22.04

    sudo apt update
    sudo apt install -y docker.io docker-compose-v2
    sudo systemctl enable --now docker
    docker --version
    docker compose version

### 4.3 配置镜像加速（强烈建议）

    sudo mkdir -p /etc/docker
    sudo tee /etc/docker/daemon.json <<'EOF'
    {
      "registry-mirrors": ["https://你的专属加速地址.mirror.aliyuncs.com"]
    }
    EOF
    sudo systemctl daemon-reload
    sudo systemctl restart docker

专属加速地址：阿里云控制台 → 容器镜像服务 ACR → 镜像工具 → 镜像加速器。

## 五、把代码与构建产物放到服务器

### 5.1 上传代码

方式 A：服务器能访问 GitHub 时，直接 clone

    mkdir -p /opt/blog && cd /opt/blog
    git clone https://github.com/你的用户名/personal-blog.git .

方式 B：本地打包上传（服务器访问 GitHub 慢时推荐）

在本地项目根目录：

    # 打包（排除 node_modules、target 等大目录）
    tar -czf blog-src.tar.gz --exclude=node_modules --exclude=target --exclude=dist .
    scp blog-src.tar.gz root@你的公网IP:/opt/

服务器上：

    mkdir -p /opt/blog && cd /opt/blog
    tar -xzf /opt/blog-src.tar.gz

### 5.2 准备构建产物（推荐在本地构建后上传）

原因：2 核 2G 服务器上跑 Maven / npm 构建容易内存不足、速度慢。

本地执行：

    # 1) 后端打 jar（在 blog-backend 目录）
    cd blog-backend
    mvn -DskipTests package
    # 产物：target/blog-backend-1.0.0.jar

    # 2) 前端构建（在 blog-web 目录）
    cd ../blog-web
    npm install
    npm run build
    # 产物：dist/

上传到服务器（在本地项目根目录执行）：

    ssh root@你的公网IP "mkdir -p /opt/blog/blog-backend/target"
    scp blog-backend/target/blog-backend-1.0.0.jar root@你的公网IP:/opt/blog/blog-backend/target/
    scp -r blog-web/dist root@你的公网IP:/opt/blog/blog-web/

> 如果服务器配置够（4G 内存以上），也可以直接在服务器安装 JDK17 + Maven + Node18 后执行同样的构建命令。

## 六、配置环境变量

服务器上：

    cd /opt/blog
    cp .env.example .env
    vi .env

把三个值改成强密码：

    MYSQL_ROOT_PASSWORD=你的MySQL密码
    REDIS_PASSWORD=你的Redis密码
    JWT_SECRET=至少32位随机字符串

生成随机 JWT 密钥：

    openssl rand -base64 32

注意：
- .env 已被 .gitignore 忽略，不会提交到 Git；
- 数据库 / Redis 密码不要用弱密码。

## 七、启动服务

    cd /opt/blog
    docker compose up -d --build

说明：
- 首次启动会自动拉取镜像、构建后端镜像；
- MySQL 容器首次初始化时会自动执行 sql/schema.sql（建表）和 sql/data.sql（初始化数据）；
- 后端首次启动会自动创建管理员账号 admin / 123456。

查看状态与日志：

    docker compose ps
    docker compose logs -f backend
    docker compose logs -f mysql

## 八、验证

浏览器打开：

    http://你的公网IP/

前台首页应能打开；后台：

    http://你的公网IP/admin/login

用 admin / 123456 登录，能进入仪表盘即部署成功。

命令行快速验证：

    curl -i http://你的公网IP/api/category/list
    curl -i http://你的公网IP/doc.html

## 九、域名与 HTTPS

### 9.1 绑定域名

- 域名 A 记录指向 ECS 公网 IP；
- 修改 nginx/blog.conf 中的 server_name（把 _ 改成你的域名），例如 server_name blog.example.com;
- 重启：docker compose restart nginx

### 9.2 申请证书

推荐阿里云「数字证书管理服务」申请免费 DV 证书（或 Let's Encrypt）。

下载 Nginx 格式证书后，放到：

    /opt/blog/nginx/certs/fullchain.pem
    /opt/blog/nginx/certs/privkey.pem

### 9.3 配置 HTTPS

在 nginx/blog.conf 中追加（或替换为）HTTPS 配置：

    server {
        listen 443 ssl;
        server_name blog.example.com;

        ssl_certificate     /etc/nginx/certs/fullchain.pem;
        ssl_certificate_key /etc/nginx/certs/privkey.pem;

        root /usr/share/nginx/html;
        index index.html;

        location / {
            try_files $uri $uri/ /index.html;
        }

        location /api/ {
            proxy_pass http://backend:8080/api/;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
        }
    }

    # HTTP 自动跳转 HTTPS
    server {
        listen 80;
        server_name blog.example.com;
        return 301 https://$host$request_uri;
    }

然后：

    docker compose restart nginx

## 十、上线安全与运维检查清单

- [ ] 修改默认管理员密码（见 10.1）
- [ ] .env 中数据库 / Redis / JWT 都是强密码，且未提交到 Git
- [ ] 安全组只开放 22 / 80 / 443，3306 / 6379 不暴露公网
- [ ] 生产环境关闭或限制接口文档（注释 nginx 中 /doc.html、/v3/ 配置）
- [ ] 数据库定期备份（见 11.3）
- [ ] 服务器设置快照 / 监控告警
- [ ] 开启 HTTPS 后，前端访问地址改为 https

### 10.1 修改管理员默认密码

项目当前没有「修改密码」接口，上线前建议：
1. 先用 SQL 修改（需要 BCrypt 哈希），或
2. 后续补一个修改密码接口（推荐）。

生成 BCrypt 哈希（本机有 JDK 时，用 Maven 仓库里的 spring-security-crypto 包）：

    jshell --class-path "$HOME/.m2/repository/org/springframework/security/spring-security-crypto/6.2.4/spring-security-crypto-6.2.4.jar"
    > new org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder().encode("新密码")

拿到哈希后：

    docker compose exec mysql mysql -uroot -p
    USE blog;
    UPDATE blog_user SET password='生成的BCrypt哈希' WHERE username='admin';

## 十一、常用运维命令

### 11.1 服务管理

    cd /opt/blog
    docker compose ps                 # 查看状态
    docker compose logs -f backend    # 看后端日志
    docker compose restart backend    # 重启后端
    docker compose up -d --build      # 重新构建并启动（代码更新后）
    docker compose down               # 停止并删除容器（保留数据卷）
    docker compose down -v            # 连数据卷一起删除（会清空数据库！慎用）

### 11.2 更新代码后重新部署

本地重新构建 jar / dist → 上传 → 服务器执行：

    cd /opt/blog
    docker compose up -d --build

### 11.3 数据库备份与恢复

    # 备份
    docker compose exec mysql mysqldump -uroot -p你的密码 --databases blog > backup-$(date +%F).sql

    # 恢复
    docker compose exec -T mysql mysql -uroot -p你的密码 < backup-2026-11-18.sql

建议用 crontab 每天自动备份。

### 11.4 查看资源占用

    docker stats
    df -h
    free -h

## 十二、常见问题排查

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 浏览器打不开公网 IP | 安全组未开放 80 | 检查安全组入方向规则 |
| 页面 404 / 白屏 | dist 未上传 / 挂载路径不对 | 确认 /opt/blog/blog-web/dist 有 index.html |
| /api 返回 502 | 后端容器没起来 | docker compose logs backend 看报错 |
| 后端启动报数据库连接失败 | mysql 未就绪 / 密码不对 | 看 mysql 日志，核对 .env |
| 登录接口 5000 | Redis 密码不对或未启动 | 核对 .env 的 REDIS_PASSWORD |
| 拉镜像很慢 / 超时 | 未配置镜像加速 | 配置 registry-mirrors 后重启 docker |
| MySQL 首次初始化失败 | schema.sql 语法或权限问题 | docker compose logs mysql 查看 |
| 中文显示乱码 | 时区/字符集 | 已配置 utf8mb4 与 Asia/Shanghai |
| 端口 80 被占用 | 服务器已有 nginx/apache | systemctl stop nginx 或改端口映射 |

## 十三、附：不用 Docker 的部署方式（简版）

如果不想用 Docker，也可以直接在服务器安装环境：

1. 安装 JDK 17、MySQL 8、Redis 7、Nginx；
2. 导入 sql/schema.sql 与 sql/data.sql；
3. 上传 jar，用 systemd 托管（/etc/systemd/system/blog.service）：

    [Unit]
    Description=Blog Backend
    After=network.target
    [Service]
    ExecStart=/usr/bin/java -jar /opt/blog/blog-backend-1.0.0.jar --spring.profiles.active=prod
    Restart=always
    [Install]
    WantedBy=multi-user.target

4. 上传前端 dist 到 Nginx 的 html 目录，配置 Nginx 反向代理 /api；
5. systemctl enable --now blog && systemctl restart nginx

> 不推荐新手用这种方式（环境不一致、排错麻烦），Docker Compose 更省心。
